\subsubsection{Sliding-Window Frequency Control Algorithm}
The Anomalous Packet Inspector tracks sensor packet frequencies using a sliding-window log algorithm. For each incoming packet from sensor $s_i$ arriving at timestamp $t_{now}$, the inspector executes the following atomic algorithm:
\begin{enumerate}
    \item Compute the lower timestamp bound of the rolling window: $t_{window} = t_{now} - 10.0\text{ seconds}$.
    \item Remove all expired timestamps belonging to sensor $s_i$ where $t < t_{window}$.
    \item Query the cardinality of the remaining log entries: $k = |\{t \in \mathcal{L}(s_i) : t \ge t_{window}\}|$.
    \item If $k \ge 50$, trigger an anomaly rejection: record an audit drop event and discard the packet.
    \item If $k < 50$, append $t_{now}$ to $\mathcal{L}(s_i)$ and permit the packet to advance to physical validation.
\end{enumerate}

In production, this algorithm is implemented via Redis Sorted Sets using an atomic Lua script:
\begin{verbatim}
redis.call('ZREMRANGEBYSCORE', KEYS[1], '-inf', ARGV[1])
local current = redis.call('ZCARD', KEYS[1])
if current >= tonumber(ARGV[2]) then
    return 0
else
    redis.call('ZADD', KEYS[1], ARGV[3], ARGV[3])
    redis.call('EXPIRE', KEYS[1], 15)
    return 1
end
\end{verbatim}
This achieves strict $\mathcal{O}(\log N + M)$ time complexity, executing in under 0.2~ms per packet.

\subsubsection{Physical Bound Consistency Verification}
Packets passing frequency control are subjected to domain-specific physics validation implemented in \texttt{payload\_validator.py}:
\begin{equation}
\mathcal{V}(P) = \begin{cases}
\text{Valid} & \text{if } P.\text{type} = \text{water} \land P.\text{flow} \ge 0.0 \land 0.0 \le P.\text{pH} \le 14.0 \\
\text{Valid} & \text{if } P.\text{type} = \text{energy} \land P.\text{kWh} \ge 0.0 \land 0.0 \le P.\text{PF} \le 1.0 \\
\text{Valid} & \text{if } P.\text{type} = \text{air} \land 0.0 \le P.\text{AQI} \le 500.0 \land 0.0 \le P.\text{humidity} \le 100.0 \\
\text{Invalid} & \text{otherwise}
\end{cases}
\end{equation}
Any sensor reading outside these physically possible boundaries indicates hardware malfunction or malicious packet injection and is rejected immediately.

\subsection{Persistence Circuit Breaker State Machine}
To safeguard the gateway process against unhandled database exhaustion or high-latency downstream bottlenecks, the persistence layer incorporates a self-healing Circuit Breaker pattern (\texttt{circuit\_breaker.py}). The breaker models three distinct states:
\begin{enumerate}
    \item \textbf{CLOSED (Normal Operation):} All sanitized telemetry packets are dispatched to the \texttt{TimescaleDB} connection pool. The breaker tracks the sliding average of execution latencies over the last 100 persistence operations.
    \item \textbf{OPEN (Failure Suspension):} If consecutive batch persistence latency exceeds 2,000~ms or if three consecutive connection timeouts occur, the circuit breaker trips to \texttt{OPEN}. In this state, incoming telemetry persistence is immediately halted to prevent thread pool exhaustion, returning HTTP 503 to ingress callers.
    \item \textbf{HALF-OPEN (Cautious Probing):} After a configured cooling interval (default: 30 seconds), the circuit transitions to \texttt{HALF-OPEN}, admitting a single canary batch. If the canary insert succeeds within $< 500$~ms, the breaker resets to \texttt{CLOSED}; otherwise, it re-trips to \texttt{OPEN} for an exponential backoff period.
\end{enumerate}
